## Qué es cada uno

**Software estándar.** Un programa ya construido, pensado para muchas empresas. Hoy casi siempre se contrata como servicio (SaaS): se paga una cuota mensual por usuario y se usa a través del navegador. Se adapta a cada empresa con opciones de configuración.

**Software a medida.** Un programa que se diseña y se construye para una empresa concreta, a partir de cómo trabaja. No tiene nada que la empresa no use ni le falta nada que necesite.

Entre los dos hay un terreno intermedio: **programas estándar con desarrollos adicionales**, o **programas estándar conectados entre sí** mediante integraciones y automatizaciones.

## Comparativa

| | Software estándar | Software a medida |
| --- | --- | --- |
| Inversión inicial | Baja | Alta |
| Coste recurrente | Licencias por usuario, que crecen con el equipo | Mantenimiento y alojamiento |
| Tiempo de implantación | Corto | Más largo; se entrega por fases |
| Ajuste al proceso | La empresa se adapta al programa | El programa se adapta a la empresa |
| Evolución | La decide el fabricante | La decide la empresa |
| Integraciones | Las que ofrezca el fabricante | Las que se necesiten |
| Propiedad | Se alquila | Es de la empresa |
| Riesgo principal | Que no encaje y se trabaje por fuera | Depender de quien lo construyó |

## Cuándo elegir software estándar

- **El proceso es común.** Contabilidad, facturación, nóminas, correo, videollamadas. Son iguales en casi todas las empresas y, a menudo, están regulados.
- **Se necesita ya.** Un estándar puede estar funcionando en días.
- **El presupuesto inicial es limitado.**
- **No se sabe todavía qué se necesita.** Usar un estándar una temporada es la mejor forma de descubrirlo.

## Cuándo compensa el software a medida

- **El proceso es lo que te diferencia.** Si tu forma de presupuestar, fabricar o atender es tu ventaja, meterla en el molde de un programa genérico es perderla.
- **El estándar no encaja y el equipo trabaja por fuera.** La señal más clara: hojas de cálculo paralelas, datos duplicados, pasos que «el programa no deja hacer».
- **Hay muchos sistemas que conectar** y ninguno hace de centro.
- **Las licencias pesan.** Con muchos usuarios, la cuota mensual de varios años supera lo que cuesta construir.
- **El producto o servicio es a medida.** Cuando cada pedido es distinto, los programas pensados para producto estándar se quedan cortos. Lo vemos a menudo en [industria y fabricación](/sectores/industria-y-fabricacion/).

## La opción que suele olvidarse: combinar

No hay que elegir una sola cosa para toda la empresa. Lo que mejor funciona en la mayoría de los casos:

- **Estándar para lo común y regulado**: contabilidad, facturación, nóminas.
- **A medida para lo propio**: la operación que diferencia a la empresa.
- **Integraciones entre ambos**, para que los datos pasen de uno a otro sin copiarlos.

Y antes de construir nada, comprobar si el problema se resuelve **conectando lo que ya hay**. Muchas veces el programa no es malo; es que no habla con los demás. Esa [integración de sistemas](/soluciones/integracion-de-sistemas/) cuesta una fracción de un desarrollo nuevo.

## Cómo decidir: cinco preguntas

1. **¿Este proceso es igual que el de cualquier otra empresa?** Si sí, estándar.
2. **¿He probado de verdad un programa estándar?** Si no, pruébalo antes.
3. **¿Cuánto trabajo se hace hoy fuera del programa?** Si es mucho, el estándar no está encajando.
4. **¿Cuánto cuesta el estándar a cinco años**, sumando licencias, adaptaciones y el tiempo perdido?
5. **¿Qué pasa si el fabricante sube el precio o cambia el producto?**

## Los riesgos del software a medida, y cómo reducirlos

| Riesgo | Cómo se reduce |
| --- | --- |
| Depender del proveedor | Propiedad del código y documentación desde el primer día |
| Que el alcance crezca sin control | Entregas por fases, cada una con un resultado utilizable |
| Que tarde demasiado en dar resultado | Empezar por el tramo del proceso que más tiempo ahorra |
| Mantenimiento descuidado | Acuerdo de mantenimiento con plazos de respuesta |
| Construir lo que no hacía falta | Estudiar el proceso antes de escribir una línea de código |
